# mirin's GPUI fork

`gpui` 0.2.2 from crates.io (Zed Industries, Apache-2.0), forked in the monorepo (`forks/gpui`) so
`mirin-metal` can extend layout where the published crate stops short. Every
change is listed here and marked with a `// mirin:` comment in the source.
Upstreaming candidates are marked as such.

| Change | Files | Why |
| --- | --- | --- |
| Explicit grid track lists (`grid_template_columns` / `grid_template_rows`) | `src/style.rs`, `src/taffy.rs` | Tailwind `grid-cols-[16px_1fr]`, `grid-cols-[1fr_auto]`; the published crate only has `repeat(N, minmax(0, 1fr))`. Upstreamable. |
| `justify_items` / `justify_self` | `src/style.rs`, `src/taffy.rs` | Grid inline-axis alignment (`justify-self-end`, `justify-items-center`). Upstreamable. |
| Text min-content width is the widest word | `src/elements/text.rs` | Taffy asks text for its min-content size when sizing `auto`/`1fr` grid tracks and flex items; GPUI returned the unwrapped line, so text never wrapped there (a card header's title column pushed its action out of the card). Upstreamable. |
| wlr-layer-shell surfaces (`WindowOptions::layer_shell`, `LayerShellOptions`) | `src/platform.rs`, `src/window.rs`, `src/platform/linux/wayland/{client,window}.rs`, `src/platform/mac/window.rs`, `Cargo.toml` | Desktop-shell UI (menu bar, dock, launcher) are layer surfaces; GPUI only made xdg toplevels. The Wayland window's surface role became an enum, toplevel-only requests are no-ops on layer surfaces, and `wayland-protocols-wlr` 0.2 is a new optional dependency. Upstreamable in spirit (Zed would want its own API shape). |
| Typed float literals in `to_grid_repeat` | `src/taffy.rs` | rustc is phasing out `f32` fallback for untyped literals (future hard error). |
| Session-lock surfaces (`WindowOptions::session_lock`, `Window::unlock_session`) | `src/platform.rs`, `src/window.rs`, `src/platform/linux/wayland/{client,window}.rs`, `src/platform/mac/window.rs` | A lock screen: ext-session-lock-v1 on the first output; unlocks only on request, never on exit. |
| Layer surfaces on a chosen screen (`LayerShellOptions::output`) | `src/platform.rs`, `src/platform/linux/wayland/{client,window}.rs` | A desktop shell puts a menu bar on every screen; GPUI passed no output to `get_layer_surface`. The client keeps the bound `wl_output` proxies and looks the name up when the window opens. The client does one roundtrip at startup so every output's name has arrived before a window can open; without it a host that opened its window at once found no output of that name and its surface landed on the compositor's pick (every second screen's menu bar on the first). |
| Wayland windows commit only drawn frames; idle windows wake on dirty (`PlatformWindow::redraw_waker`) | `src/platform.rs`, `src/window.rs`, `src/platform/linux/wayland/window.rs` | GPUI committed after every frame callback even when nothing was drawn, which asked for another callback: an unchanged window committed at the display's rate and kept an on-demand compositor drawing (and the GPU awake) forever. Now a frame callback is asked for only when a frame draws, a window with nothing to draw goes idle, and GPUI wakes it when it becomes dirty or wants its next frame. Upstreamable. |
| The event loop can outlive its last window (`set_quit_when_last_window_closes`) | `src/platform.rs`, `src/platform/linux/{wayland,x11}/client.rs` | A resident host (`mirin-metal-host` with `MIRIN_METAL_DEFERRED=1`) hides its only window and opens one again later; Linux's clients stopped the loop when the last window was dropped, so the process quit on a hide. On by default, as upstream; an app that turns it off quits itself. Upstreamable. |
| Text input only while a field takes text (`PlatformWindow::set_accepts_text`); the caret is the input method's area before anything is composed | `src/platform.rs`, `src/window.rs`, `src/platform/linux/wayland/{client,window}.rs` | GPUI turned Wayland's text input on for every focused window, whether or not anything took its text: an input method composed over a list or a password field and its text went nowhere (or saw the password). Now each frame says whether it set an input handler, and text input is on only while one is set and the window has the keyboard. With nothing composed, the area GPUI tells the compositor is the caret (the selection's head), so the candidates open under it from the first key. Upstreamable. |
| Unified title bar on Dashi (`TitlebarOptions::appears_transparent` binds Dashi's private `dashi_chrome_manager_v1`; `Window::chrome_controls`, `Window::observe_window_chrome`, `PlatformWindow::chrome_controls` / `on_chrome_changed`) | `protocols/dashi-chrome-v1.xml`, `src/platform.rs`, `src/window.rs`, `src/platform/linux/wayland.rs`, `src/platform/linux/wayland/{dashi_chrome,client,window}.rs`, `Cargo.toml` | A Wayland window with a transparent title bar asks Dashi's compositor, before its first commit, for the unified style: no compositor title bar, its traffic lights drawn over the window. The compositor's `controls` event (the lights' area) is exposed so the app can keep it empty. Other compositors lack the global: the window keeps the standard server-side title bar and the area is `None`. The XML is a copy of `dashi/comp/protocols/dashi-chrome-v1.xml`; `wayland-scanner` (already in the tree) is a new optional dependency. Dashi-specific; not upstreamable. |
| Toplevel suspended state (`xdg_wm_base` bound up to version 6; `Window::is_window_suspended`, `Window::observe_window_suspended`; `PlatformWindow::is_suspended` / `on_suspended_changed`) | `src/platform.rs`, `src/window.rs`, `src/platform/linux/wayland/{client,window}.rs` | A window out of sight (minimized, on another desktop) should stop polling and drawing; the compositor says so with xdg_toplevel's `suspended` state (xdg-shell 6), which GPUI never bound or read. A configure's states now set the flag, and a change runs the observers. Other platforms report false. Upstreamable. |
| A text layout is reused only for the same truncation width (`reuses_layout`) | `src/elements/text.rs` | A one-line text that ends in an ellipsis has no wrap width, so the cache (keyed on the wrap width alone) handed taffy's later query at the real width the whole line from its first, unbounded one: wherever a flex item's width came from its content (`flexShrink: 1`, `maxWidth`), the line was clipped mid-glyph with no ellipsis. `reuses_layout` is public, hidden, so mirin-metal's tests reach it. Upstreamable. |
| Per-paragraph font sizes (`StyledText::with_paragraph_sizes`, `TextLayout::line_height_for_index`) | `src/elements/text.rs` | An editable field that formats as it is typed (a note's headings) draws one paragraph larger than the rest: each paragraph is shaped at its own size and each line keeps its own line height, which painting, hit-testing and `position_for_index` follow. GPUI shaped a text at one size. Upstreamable in spirit. |
| A truncated line is cut where it is drawn (`TextLayout::fit_to`; the measure cache keys on the cut width too; the runs are cut on a copy) | `src/elements/text.rs` (tests `mirin_truncate_tests`) | A nowrap line with `text-overflow: ellipsis` was measured first at max-content, and that uncut layout was reused for every later width (the cache keyed only on the wrap width, which a nowrap line doesn't have), so a line that ran out of room was clipped mid-letter with no ellipsis (Software's card names, Installed's detail lines). The measure also cut the captured runs in place, so a second measure shaped the whole text with runs for the cut one. Now a cut is remeasured per width, and prepaint cuts the line again when taffy places it at another width than its last measure. Upstreamable. |
| A resize asked of a maximized or full-screen window keeps its size and moves the size it goes back to by as much | `src/platform/linux/wayland/window.rs` | An app that widens its window to show a sidebar (`setSize`) while zoomed set the window's geometry, and the compositor took it out of the maximized state at the new size. Now the window keeps the compositor's size and the sidebar's room is added to the size it is restored to. Upstreamable. |
| A line cut to a width narrower than its ellipsis draws nothing | `src/text_system/line_wrapper.rs` (`truncate_line`; tested in mirin-metal's `render::one_line_tests`) | The cut kept the suffix whatever the width, so a box a few px wide (a title's detail with nothing left) drew a sliver of "…" clipped at its edge. Upstreamable. |
| A line is cut from a copy of its runs (`cut_line`) | `src/elements/text.rs` (tested in mirin-metal's `render::one_line_tests`) | Since a layout is reused only for the same cut, taffy measures a one-line text more than once, and a cut made in place gave the next measure the runs of the shorter line: the rest of the line lost its color (Calendar's white chip titles drew in the default ink, review 54). Upstreamable. |
| The least size can change after the window opened (`PlatformWindow::set_min_size`, `Window::set_window_min_size`) | `src/platform.rs`, `src/window.rs`, `src/platform/linux/{wayland,x11}/window.rs` | An app that needs more room while it shows more (a sidebar beside a fixed column) raises its least size, and lowers it when the sidebar goes; GPUI took one only at open. Wayland sends `xdg_toplevel.set_min_size` (applied with the next frame, which it asks for), X11 updates `WM_NORMAL_HINTS`; other platforms keep the first. Upstreamable. |
| A wrapped line is aligned by where its ink ends (`ink_end_x`) | `src/text_system/line.rs` | A right-aligned or centered text that wrapped at a space kept that space at the end of the line, so the line ended a space short of the lines under it (a wrapped sum in Dashi's Calculator tape). The space stays in the text; it takes no room when the line is aligned. `ink_end_x` is public (hidden) so mirin-metal tests it. Upstreamable. |
| A no-break space, the word joiner and typographic quotes keep their words together | `src/text_system/line_wrapper.rs` (`is_word_char`, tests `test_is_word_char`, `test_wrap_line_keeps_a_no_break_space`) | U+00A0 and U+202F were break opportunities, so "the\u{00A0}Trash." still left "Trash." alone on a line; and "you’re" or "“Notes.txt”" could break at the curly quote. Upstreamable. |
| A scroll view scrolls by taffy's content size (`Window::layout_scroll_extent`, `TaffyLayoutEngine::layout_scroll_extent`; `Interactivity::scroll_extent`) | `src/taffy.rs`, `src/window.rs`, `src/elements/div.rs` (tested in mirin-metal's `render::scroll_tests`) | The range was the span between the children's border boxes plus the padding: the last child's end margin and the view's border were left out, and an absolutely placed child at the view's corner (mirin's scroll bar) moved the span's start up to it, so the top padding counted twice and the view scrolled past its end by it. Now it is CSS's scrollable overflow as taffy measured it, plus the end border, less the size. Upstreamable. |
| The wheel scrolls the innermost view that can still move, then the one around it (`wheel_scroll`; `ListState::scroll` says whether it moved) | `src/elements/div.rs`, `src/elements/list.rs` (tested in mirin-metal's `render::scroll_tests`) | Every scroll view under the pointer took every turn, unclamped until the next frame, so a list in a page scrolled the page with it. Now a view that moved stops the event; at its end it lets it bubble. Upstreamable. |
| A list's scroll bar range counts its padding (`ListState::max_offset_for_scrollbar`) | `src/elements/list.rs` | `scroll` counted the list's padding in its range and the scroll bar's range didn't, so a thumb never reached the end of its track. Upstreamable. |
| Retained subtrees (`retained(id, view, version, build)`, `Retained::on_prepaint`, `RetainedDraw`) | `src/elements/retained.rs` (+ `retained/{state,draw,recording,masks,region,moved,tests}.rs`), `src/elements/mod.rs`, `src/window.rs` (`ElementStateScope`, `retained_detached`, `recordings`, `element_state_scopes`, `prepaint_range_valid`, `paint_range_valid`, `compute_detached_layout`, `layout_engine`; `PrepaintStateIndex`/`PaintIndex` fields crate-visible), `src/text_system.rs`, `src/text_system/line_layout.rs` (`layouts_range_valid`, `LineLayoutIndex` fields crate-visible) | GPUI rebuilt, laid out, prepainted and painted the whole tree every frame, so a 15k-node window cost ~150 ms per frame whatever changed. A retained subtree is built only when its content `version` changes or its `view` is notified; otherwise its taffy nodes stay in the tree with taffy's cache, and where it lands as it was drawn last frame its prepaint and paint ranges are copied. Unlike `AnyView::cached` it may size itself from its content, and subtrees nest: the ranges a nested one keeps are moved along when the one around it is copied, and one built again adopts the clean ones inside it. `window.refresh()` does not rebuild it: what it draws must depend on its content and on state that notifies its view. Upstreamable in spirit. |
| A retained subtree that moved keeps its drawing (`Retained::movable`; `Window::reuse_prepaint_moved`/`reuse_paint_moved`, `Scene::replay_moved`, `Frame::content_masks`/`hitbox_masks`, `Scene::operation_masks`, `MaskNode`, `MaskMap`) | `src/elements/retained/{state,draw,masks}.rs`, `src/window.rs` (`with_content_mask`, `insert_hitbox`, the reuse functions, `PrepaintStateIndex`/`PaintIndex::content_masks_index`), `src/scene.rs` | One that landed elsewhere (it scrolled, or what is above it grew) was built, laid out and drawn again: a scrolled frame cost what it did without retention. Its hitboxes and primitives are now copied moved, each under the content mask it has there: the frame keeps every mask as it was pushed and the one around it, so the masks pushed inside the subtree move with it and are intersected again with the ones around it. Only when the copy is what drawing it there gives: its layout inside did not change (taffy's `inner_changed_since`), it moved by whole device pixels from and to whole pixels at a scale factor of 1, 2 or 4 (elsewhere `n / scale * scale` is not `n`, and GPUI floors and rounds positions), not across when it has glyphs (they snap to a fraction of a pixel from their own position), not at all when a glyph sits within 1/128 px of a pixel edge or an icon rounds a half pixel or is rotated, and when the pointer is over neither where it was nor where it lands (a hover style is painted from what is under the pointer). A `div` with a tooltip, a drag, a drop or a group style, a deferred draw, an input handler and a window-control hitbox pin the subtree they are in. Upstreamable in spirit. |
| A retained subtree's drawing is whole, or says where it is (`Recording`, `Region`, `Window::cull_mask`, `Scene::keep`, `Inserted`; a layer keeps its own bounds and mask) | `src/elements/retained/{recording,region}.rs`, `src/window.rs` (`insert_primitive`, `paint_layer`, `paint_glyph`, `paint_emoji`, `paint_svg`, `defer_draw`, `handle_input`), `src/scene.rs` (`insert`, `push_layer`), `src/text_system/line.rs` | Elements leave out what their content mask hides (a line's glyphs, any primitive), so a drawing made while clipped has holes where it was. A subtree drawn anew culls against its mask grown by 256 px instead, keeps primitives and layers that are hidden there as paint operations (not drawn), and narrows the region its drawing is whole in by what was left out all the same (and by the subtrees inside it that were left undrawn, unless a mask of its own hides them); it is moved only where the content mask stays inside that region. A row scrolled into view is so drawn once, not on every frame until all of it shows. |
| A retained subtree nothing shows of is not drawn (`Retained::skippable`; `DispatchTree::range_is_inert`, `Window::dirty_unseen`) | `src/elements/retained/{state,draw}.rs`, `src/key_dispatch.rs`, `src/window.rs` (`mark_view_dirty`) | Rows out of a scroll view (or of an `overflow: hidden` box) were copied every frame: hitboxes, listeners, dispatch nodes. One that was drawn once (so how far it reaches is known), takes no keys, focus, text or deferred draw, and whose caller says nothing in it needs events while unseen, is left out while nothing of it shows; a subtree around it that copied it before is drawn again once to drop it. A view notified inside one left undrawn has no place in last frame's dispatch tree, so the subtrees around it look for it among the ones they hold. |
| A retained subtree is built again onto the layout it kept (`TaffyLayoutEngine::begin_bind`/`end_bind`/`fail_bind`, `epoch`, `inner_changed_since`; `Window::request_measured_layout_keeping`; `take_built_apart`) | `src/taffy.rs`, `src/elements/retained/draw.rs` (`rebuild`), `src/window.rs`, `src/elements/text.rs` (`TextLayoutInner: Clone`, `layout_sized`) | One whose drawing can't be copied (it moved by a fraction of a pixel, or it holds a subtree that came into view) was built apart and laid out again as a detached copy, with everything inside it. Its elements are now built for the nodes it kept: each layout request is answered with the node made last time, in the same order (checked: same children, same kind), so nothing is laid out and the retained subtrees inside it are each copied, moved, left out or built their own way. A measured leaf takes the new element's function, which is asked what the old one was last asked (taffy's `last_measure_inputs`); a text finds the lines the element before it shaped on the node and answers from them. Only while none of the subtree's own texts was measured again since the layout its nodes were made in (taffy's `asked_since`): after that a text may hold the answer to a size its parent was only trying out, not what a layout from nothing leaves it with. Such a subtree, and one whose elements ask for anything else than the nodes it kept (or lay out by themselves), is laid out as a detached copy as before (`take_built_apart` counts them). |
| A reused drawing is placed among what is drawn as one (`BoundsTree::insert_spanning`, `Scene::replay_moved`'s `whole`, `Scene::push_ordered`) | `src/bounds_tree.rs`, `src/scene.rs` | Replaying a drawing inserted each primitive into the bounds tree again to find its draw order: a third of a frame that reused most of the window. A drawing that shows exactly what it did (in place, or moved with nothing around it clipping it before or after) is inserted once, as its bounds: its primitives keep their draw orders among themselves, rebased above what is under them, and what is drawn over its bounds later comes after them all. What overlaps is painted in the same order as before; the numbers differ, so `retained/tests.rs` compares what is painted over what (`Scene::stacking`). `Window::reuse_paint` (`AnyView::cached`, deferred draws) keeps upstream's way. Upstreamable. |
| `Window::scene_drawn`, `scene_digest` (hidden) | `src/window.rs`, `src/scene.rs` (`describe`) | The primitives and hittable hitboxes of the frame being painted, without draw orders or atlas places, and a digest of them: mirin-metal traces it (`MIRIN_METAL_TRACE_SCENE`) so a check can tell that retained subtrees draw what drawing everything does, with real text (it found the accordion text above). |
| Element states of a retained subtree live in its own state (`with_element_state` stores into the innermost `ElementStateScope`) | `src/window.rs`, `src/elements/retained.rs` | GPUI moved every element state from last frame's map to the next frame's every frame, cloning and hashing each element's full id path: a third of a frame that reused everything. A reused subtree now carries its elements' states as one entry. |
| The layout engine keeps a tree across frames (`begin_owned`/`end_owned`, `remove_nodes`, `released`, `contains`; `clear` frees only the frame's own nodes and released subtrees, or everything when nothing is retained) | `src/taffy.rs` | Retained subtrees keep their taffy nodes and cache; the measure function is shared with the detached layout. |
| The fork's taffy by path (`[dependencies.taffy] path = "../taffy"`) | `Cargo.toml` | The retained subtrees use the taffy fork's API (incremental rounding, detached layout, `contains`), also when this crate is built alone for its tests. |
| `DispatchEventResult` is public (hidden) | `src/window.rs` | It was a private type in `Window::dispatch_event`'s public signature, which made the method uncallable from outside; mirin-metal's simulated pointer moves (sim `move`) dispatch through it. Upstreamable. |

To update: see `../README.md` (merge the `forks-upstream` branch), then
reconcile the changes above.

To run the fork's own tests (the `mirin` ones among them): it isn't a
workspace member, so build it alone with mirin-metal's lockfile:
`cp ../../crates/mirin-metal/Cargo.lock . && CARGO_TARGET_DIR=../../crates/mirin-metal/target/gpui-alone cargo test --lib --features test-support`,
then remove the copied `Cargo.lock`.
