# mirin's taffy fork

`taffy` 0.9.0 from crates.io (DioxusLabs, MIT), forked in the monorepo (`forks/taffy`) because GPUI pins
`taffy = "=0.9.0"` and its flexbox base-size step diverges from the spec in a
way shadcn layouts hit. Every change is marked with a `// mirin:` comment.

| Change | Files | Why |
| --- | --- | --- |
| A flex container whose width its `min-width` or `max-width` set (not its content) lays its children out again at that width | `src/compute/flexbox.rs` (`compute_flexbox_layout`, test `mirin_tests`) | Under a min-content (or max-content, or definite available) width the children were laid out for the content's width, each text wrapped at its widest word, and the container then clamped to its `min-width`; the height that came back belonged to the unclamped width. `Cache::get` reuses an entry whose size equals the known one, so a parent that then asked for exactly that width got the word-by-word height: Dashi's Settings row (words `flex: 1` with `min-width: 120` beside a 260 slider) grew more than twice as tall at its least width. Only a width at a bound is laid out again, so the cost is one more pass of that subtree then. Upstreamable. |
| A negative margin on an item with `flex-shrink: 0` takes off only the margin from the container's intrinsic main size | `src/compute/flexbox.rs` (`determine_container_main_size`, test `mirin_tests`) | The max-content flex fraction was divided by `max(1, flex_shrink × inner_flex_basis)` and multiplied back by `max(1, flex_shrink) × inner_flex_basis`; with `flex_shrink` 0 those differ, so a column whose 20-tall item had `margin-top: -4` came out 80 shorter, not 4, and a scroll view over it lost its range (Dashi's Settings). Upstreamable. |
| Fit-content cross size for flex base sizes in column containers | `src/compute/flexbox.rs` (`determine_flex_base_size`) | Spec 9.2.3.E sizes a non-stretched item with an auto cross size at fit-content. taffy measured it against the whole available width, so content that scales with width (an `aspect-square` day grid in a centered calendar) reported a height several times its final one, and the item kept it. Upstreamable. |
| Fit-content cross size for the hypothetical cross size of a non-stretched item in a column | `src/compute/flexbox.rs` (`determine_hypothetical_cross_size`; tested in mirin-metal's `render::one_line_tests`) | Spec 9.4.7 sizes an item with an auto cross size at fit-content. taffy measured an `align-items: center` item at its max-content width, so a box of one long line centered in a narrower column (Dashi's notice over a 480 pt window) overflowed both edges instead of wrapping. Upstreamable. |
| A flex item's end margins count toward its container's content size (scrollable overflow) | `src/compute/flexbox.rs` (`calculate_flex_item`, test `mirin_tests`) | CSS Overflow 3 counts an in-flow item's margin box; taffy counted its border box, so a scroll view (mirin's GPUI scrolls by this size) stopped short of its last item's `margin-bottom`. Upstreamable. |
| Incremental rounding (`round_changed`, `NodeData::{written, ran, rounded_at}`; `round_node` shared with `round_layout`) | `src/tree/taffy_tree.rs`, `src/compute/mod.rs` (tests `tree::taffy_tree::mirin_tests`) | `compute_layout` rounded every node of the tree after every layout. A tree kept across frames (GPUI's retained subtrees) now rounds again only nodes whose unrounded layout was written or whose algorithm ran, or whose parent moved; the result is what rounding everything gives. |
| `remove` clears a child's parent only where it is still that parent, and drops the node's context | `src/tree/taffy_tree.rs` | A kept subtree is adopted by the next frame's parent before last frame's parent is removed; removing it used to orphan the subtree. The context (a measure function and what it holds) lingered until the slot was reused. |
| `contains` | `src/tree/taffy_tree.rs` | A kept node id can outlive its node; GPUI checks before reusing one. |
| Detached layout (`compute_detached_layout_with_measure`) | `src/tree/taffy_tree.rs` | Lays a fresh copy of a subtree out as its twin is laid out where it sits (same size, parent size, and rounding position), for a retained subtree drawn again elsewhere without laying the tree around it out again. |
