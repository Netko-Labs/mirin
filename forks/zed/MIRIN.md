# mirin's fork of upstream GPUI

The GPUI crates of the zed repository (Zed Industries, Apache-2.0) at
commit `f8cfc7ed` (`../README.md` says what is here and how to re-sync),
forked in the monorepo so `crates/mirin-metal` can build on upstream GPUI
(`crates/mirin-metal/next/Cargo.toml`) beside the fork of gpui 0.2.2
(`../gpui`) until it replaces it (`docs/metal/gpui-next.md`). Every change is
listed here and marked with a `// mirin:` comment in the source. Rows that
port a change of `../gpui` say which (`../gpui/MIRIN.md`).

A pixel breadth is rounded to device pixels as upstream rounds every length. Upstreamable. |

| Text min-content width is the widest word | `crates/gpui/src/elements/text.rs` (`widest_word`; a layout is reused only for the same wrap width) | Port of `../gpui`'s row: taffy asks text for its min-content size when sizing `auto`/`1fr` grid tracks and flex items; GPUI gave no wrap width there, so the text never wrapped. With min-content wrapping, an unwrapped query must not get the wrapped size back: upstream reused any layout for a query without a wrap width. Upstreamable. |
| A scroll view scrolls by taffy's content size (`Window::layout_scroll_extent`, `TaffyLayoutEngine::layout_scroll_extent`; `Interactivity::scroll_extent`) | `crates/gpui/src/taffy.rs`, `crates/gpui/src/window.rs`, `crates/gpui/src/elements/div.rs` (tested in mirin-metal's `render::scroll_tests`) | Port of `../gpui`'s row. Upstreamable. |

Upstreamable. |
| A list's scroll bar range counts its padding (`max_scroll_offset`) | `crates/gpui/src/elements/list.rs` | Port of `../gpui`'s row (upstream now shares `max_scroll_offset` between the bar's range and its offset at the bottom). Upstreamable. |
| A line cut to a width narrower than its ellipsis draws nothing | `crates/gpui/src/text_system/line_wrapper.rs` (`truncate_line`; tested in mirin-metal's `render::one_line_tests`) | Port of `../gpui`'s row: the cut kept the affix whatever the width, so a box a few px wide drew a sliver of "…". Upstreamable. |
| Retained subtrees, in place (`retained(id, view, version, build)`, `Retained::on_prepaint`, `RetainedDraw`, `take_built_apart`) | `crates/gpui/src/elements/retained.rs`, `crates/gpui/src/elements/mod.rs`, `crates/gpui/src/window.rs` (`retained_detached`, `retained_nested`, `layout_engine_mut`, `prepaint_range_valid`, `paint_range_valid`, `PrepaintStateIndex::rebase`, `PaintIndex::rebase`), `crates/gpui/src/text_system.rs` and `text_system/line_layout.rs` (`layouts_range_valid`, `LineLayoutIndex::rebase`) | Port of `../gpui`'s first retained rows onto upstream's frame model (`docs/metal/gpui-next.md`, "Retained subtrees on upstream GPUI"): a subtree whose content and view did not change keeps its taffy nodes, and where it lands as it was drawn (bounds, content mask) last frame's prepaint and paint ranges are copied, as `AnyView::cached` copies a view's, but sized from its content and nested. Anywhere else it is built again and laid out apart as its kept nodes sit. Upstreamable in spirit. |
| Retained subtrees move, are left out, are parked and are built again onto their kept nodes (round 5; `Retained::movable`, `skippable`; `elements/retained/{plan,recording,steady,parked}.rs`) | `crates/gpui/src/elements/retained.rs` and `retained/*.rs`, `crates/gpui/src/window.rs` (`reuse_prepaint_moved`, `reuse_paint_moved`, `retained_recordings`, recording hooks in `with_content_mask`, `insert_hitbox`, `layout_bounds`, `snap_bounds`, `cover_bounds`, `paint_quad`, `paint_glyph`, `paint_emoji`, `paint_svg`, underlines; pins in `defer_draw`, `handle_input`, `set_tooltip`, window control areas; `take_element_states`, `restore_element_states`, `drawing_is_inert`, `end_bind`, `last_scene_drawn`), `crates/gpui/src/scene.rs` (`SceneReach`, `replay_moved`, hidden primitives kept near a recording's mask, `Primitive::move_by`, layers keep their unclipped bounds and mask), `crates/gpui/src/taffy.rs` (`begin_bind`/`end_bind`, measure inputs kept per node, `any_asked_since`, `below_changed_since`, `unrounded_origin`, `node_box`, steadiness of rounded edges), `crates/gpui/src/key_dispatch.rs` (`range_is_inert`, `park_nodes`/`unpark_nodes`), `crates/gpui/src/text_system/line_layout.rs` (`park_layouts`/`unpark_layouts`), `crates/gpui/src/text_system/line.rs` (glyphs kept near the mask), `crates/gpui/src/elements/div.rs` (drag, drop, tooltip and group styles pin) | Port of `../gpui`'s retained rows onto upstream's frame (`docs/metal/gpui-next.md`, section 6, round 5): a drawing laid out whole device pixels away (at a power-of-two scale) is copied there when what it rounds rounds the same and what the mask around it hid stays hidden; one nothing of shows is left out, its drawing parked within a budget and copied back; one that can't be copied is built again onto its kept nodes (no layout), so the subtrees inside are each copied, moved or left out. Upstreamable in spirit. |
| The layout engine keeps a tree across frames (`begin_owned`/`end_owned`, `released`, `contains`, `place_detached`; `clear` frees only the frame's own nodes and released ones, or everything when nothing is retained) | `crates/gpui/src/taffy.rs` | Retained subtrees keep their taffy nodes and taffy's cache. A copy laid out apart takes its twin's size and is rounded from where the twin sits (`detached_origins`), so its edges land where the twin's do: upstream snaps absolute edges. |
| A notified view is dirty itself, not only the views on its dispatch path (`Window::mark_view_dirty`) | `crates/gpui/src/window.rs` | Retained subtrees set their views on their parent's dispatch node, one after another, so the node names the last; the path from a notified sibling then skipped it, and a card's hover change was copied stale while its row was rebuilt (found by `layout-check scroll --scene` against `MIRIN_METAL_RETAIN=0`). Upstreamable (sibling `AnyView`s set on one node have the same gap). |
| A hover listener compares with what the frame paints (`hover_state.element` set at paint from the hit test) | `crates/gpui/src/elements/div.rs` | Upstream paints a hover style from the hit test but notifies only when a mouse move changes `hover_state`, which only mouse moves set: content that scrolled under a resting pointer was painted hovered, and when the pointer then left, nothing was notified; a view copied from that frame (a retained subtree, `AnyView::cached`) kept the hover color (found by `layout-check scroll --scene` against `MIRIN_METAL_RETAIN=0`). Upstreamable. |
| `Window::scene_drawn`, `scene_digest` (hidden); `Scene::describe`, `Primitive::describe` | `crates/gpui/src/window.rs`, `crates/gpui/src/scene.rs` | Port of `../gpui`'s row: the primitives and hittable hitboxes of the frame being painted, without draw orders or atlas places, and a digest of them; mirin-metal traces it (`MIRIN_METAL_TRACE_SCENE`) so `layout-check --scene` can tell that retained subtrees draw what drawing everything does. |
| The least size can change after the window opened (`PlatformWindow::set_min_size`, `Window::set_window_min_size`) | `crates/gpui/src/platform.rs`, `crates/gpui/src/window.rs`, `crates/gpui_linux/src/linux/wayland/window.rs` | Port of `../gpui`'s row, Wayland only (`xdg_toplevel.set_min_size`, applied with the next frame, which it asks for); X11 and the other platforms keep the first, as before the fork's X11 half is ported. Upstreamable. |
| A resize asked of a maximized or full-screen window keeps its size and moves the size it goes back to by as much (`restored_size`) | `crates/gpui_linux/src/linux/wayland/window.rs` | Port of `../gpui`'s row: an app that widens its window to show a sidebar while zoomed set the window's geometry, and the compositor took it out of the maximized state. Upstreamable. |
| A wrapped line is aligned by where its ink ends (`ink_end_x`, `wrapped_line_end_x`; `paint_line`, `paint_line_background` and `aligned_origin_x` take the text) | `crates/gpui/src/text_system/line.rs` (tested in mirin-metal's `render::tests`) | Port of `../gpui`'s row: a right-aligned or centered text that wrapped at a space kept that space at the end of the line. `LineLayout::paint` has no text and aligns as before. Upstreamable. |
| Vulkan alone, GL only when Vulkan has no hardware adapter that draws to the window (`WgpuContext::vulkan_instance`, `create_context_vulkan_first`) | `crates/gpui_wgpu/src/{wgpu_context,wgpu_renderer}.rs` | Upstream asks wgpu for Vulkan and GL on Linux, and enumerating GL loads Mesa's GL driver (`libgallium`, 15 MB mapped), its six threads and ~30 ms of each start into every app, for an adapter that Vulkan wins whenever it has one. A window tries an instance of Vulkan alone first (software Vulkan counts as none), then Vulkan and GL as upstream does, so a machine without Vulkan still gets a window from GL. Device recovery does the same. Footprint lane, round 5. Upstreamable. |
| No validation of indirect calls (`InstanceFlags::VALIDATION_INDIRECT_CALL` off) | `crates/gpui_wgpu/src/wgpu_context.rs` | wgpu turns it on in every release build and sets it up with each device: two compute pipelines compiled and their buffers. GPUI makes no indirect draw or dispatch. Upstreamable. |
| GPU memory in 4 MiB blocks, anything larger in its own allocation (`MemoryHints::Manual`) | `crates/gpui_wgpu/src/wgpu_context.rs` | Port in spirit of `../blade-graphics`' allocator row. Upstream's `MemoryUsage` hint starts gpu-allocator at 8 MiB device and 4 MiB host blocks and doubles each new block, so a small window's textures and buffers held blocks of 8 and 16 MiB. Upstreamable. |
| Pipelines are built on first use and shared by a context's windows (`wgpu_pipelines.rs`: `PipelineCache`, `WgpuPipelines`, `PipelineKey`) | `crates/gpui_wgpu/src/{wgpu_pipelines,wgpu_renderer,wgpu_context,gpui_wgpu}.rs` | Port of `../gpui`'s `BladePipelineCache` row. A window's renderer parsed the shaders (twice, for the subpixel variant: ~4.5 ms) and built nine pipelines, and an opaque window built them again in `update_transparency`: ~22 ms of a small app's start. Each pipeline is now built by the first frame that draws with it, for the target format and alpha mode it draws to; the shader modules and bind group layouts are made once per context, and a second window draws with what the first built. `surfaces` (macOS video) is never built. Upstreamable. |
| Path textures exist only while paths are on screen | `crates/gpui_wgpu/src/wgpu_renderer.rs` (`render_frame`) | Port of `../gpui`'s `PathTextures` row: the intermediate texture paths are drawn through and its multisampled twin (20 bytes a pixel at four samples) were made by every frame's `ensure_intermediate_textures`. Made by the first frame that has a path, freed by the first without one. Upstreamable. |
| The GPU context is made while the app starts (`WgpuContext::prepare_vulkan`, `take_prepared_vulkan`, `from_prepared_vulkan`) | `crates/gpui_wgpu/src/{wgpu_prepare,wgpu_renderer,wgpu_context,gpui_wgpu}.rs`, `crates/gpui_linux/src/linux/wayland/client.rs` | Upstream made the instance (loading the Vulkan driver, and radv's LLVM: 12–15 ms), the adapters and a device when the first window's renderer was created, after the platform had connected and the app built its window. The Wayland client starts them on a background thread as it connects; the first window takes them, makes its surface on that instance and tests the device by configuring it, as upstream's selection does, and makes its context upstream's way when that fails. Another background task parses the shader modules on that device meanwhile, and the first pipeline that needs one waits for it rather than parsing it again (`ParsedShaders`, `PipelineCache::seed_shaders`): the first frame drew 4–9 ms after it was painted, now 3–4 ms. Upstreamable. |
| A font face is loaded when a text first picks it; the system's fonts are read on a thread (`LoadedFont::font` is an `Option`, `load_face`, `load_primary`, `CosmicTextSystem::state`) | `crates/gpui_wgpu/src/cosmic_text_system.rs` | Port of `../gpui`'s two rows. Asking for a family loaded every face of it to drop those without an 'm' (74 of Noto Sans: 15.6 MB of mapped files, a few MB of heap); a face is now listed with its family and loaded, and checked for its 'm', when it is picked (the best match among those left, as upstream chose among the ones it kept); a fallback chain takes its family's first usable face, as before. The scan of the system's fonts (7–9 ms) ran on the main thread before the Wayland connection; it now runs beside it, and the first call into the text system waits for it. Upstreamable. |
| At most four background threads | `crates/gpui_linux/src/linux/dispatcher.rs` | Port of `../gpui`'s row: upstream starts a worker per core (24 on the laptop measured). mirin-specific (an editor wants its cores). |
| One connection to the system bus for the sleep and the power-mode listeners, and the sleep listener on the background executor (`LinuxCommon::system_bus`) | `crates/gpui_linux/src/linux/platform.rs` | `App::new` starts both listeners in every app, each on its own system bus connection (a zbus thread, a socket, its buffers), and the sleep listener on `smol::spawn`, which started smol's global executor thread for it: two threads and ~0.6 MB of a small app. Upstreamable. |
| The compose table is read at the first key press (`compose_context`) | `crates/gpui_linux/src/linux/wayland/client.rs` | Port of `../gpui`'s row: each keymap event read the locale's Compose file (~2 ms of every start) though a panel or a dock never hears a key. Upstreamable. |
| Startup milestones on the `mirin::startup` log target | `crates/gpui_linux/src/linux/{platform,wayland/client,wayland/window}.rs`, `crates/gpui_wgpu/src/{wgpu_context,wgpu_renderer,wgpu_pipelines,wgpu_prepare,cosmic_text_system}.rs` | Port of `../gpui`'s row: the text system, the system fonts read, the GPU context (prepared, taken, adapters enumerated, created), a window's renderer, each shader module parsed and pipeline built, each font face loaded log their time (`log::info!`, nothing without a logger); mirin-metal prints them with `MIRIN_METAL_TRACE=1`. |
| Text lays out at its line height as styled, measured sizes are not rounded up, and edges round as the default build's taffy 0.9 rounds them (`TaffyLayoutEngine::layout_bounds`, `rounded_origins`) | `crates/gpui/src/elements/text.rs` (`TextLayout::layout`), `crates/gpui/src/taffy.rs` | Layout parity with `../gpui` (round 6, `docs/metal/gpui-next.md`). Upstream snapped a text's line height to the device pixel (`Window::pixel_snap`: 9 px text, 14.56 px a line, laid out 15 tall), ceiled every measured size, and rounded each node's absolute edges (halves toward zero); the fork lays text out at the fraction and rounds as taffy 0.9 does: a node's place in its parent rounded alone (halves away from zero), its size the difference of its rounded absolute edges. So a text box was 15 px tall upstream and 14 or 15 by where it sits on the fork, and 2,990 of the grid's 3,044 nodes differed. Every Dashi app is laid out against the fork. A copy laid out apart rounds from its twin's rounded origin too. |
| A scroll view's content lands where the default build puts it: the element offset is snapped to the device pixel with halves away from zero (`Window::layout_bounds`, `retained::Place::of`) | `crates/gpui/src/window.rs`, `crates/gpui/src/elements/retained/plan.rs` | Layout parity (round 6). Upstream snapped halves toward zero; the fork's `painted_scroll` rounds to nearest, halves away from zero, so a view scrolled by 40.5 px drew its content a pixel apart on the two builds (every node of `layout-check scroll-fractional` at that step). A retained subtree's place snaps its offset the same way. |
| A view with a tracked scroll handle hands its children's bounds to `on_children_prepainted` (port of `../gpui`'s row) | `crates/gpui/src/elements/div.rs` (`Div::prepaint`) | Upstream handed it none, so mirin-metal's layout map never had a scroll view's own children (`layout-check scroll`: the banner and the grid in the scroll view were absent on every step, and the example browser's preview and sidebar rows). They are where they are painted, scrolled. |
| A retained subtree is left out only where its root moved by whole device pixels (`plan`) | `crates/gpui/src/elements/retained/plan.rs` | With edges rounded as above, what is inside a subtree moved by a fraction may round to other sizes; mirin's layout map keeps a left-out subtree's bounds moved as they were, so it must not miss that. |
| Positions near a half (or a whole pixel, for floors) that `f32` can't move across are held, not fixed (`Steadiness::{near, range}`, `holds_within`), and a move by whole pixels give or take what `f32` lost is a move (`plan::whole_move`) | `crates/gpui/src/elements/retained/{steady,plan}.rs` | Text a fraction of a pixel tall puts many edges within 1/64 of a half, each of which fixed its axis, so rows could no longer move (a test's 8 rows: 6 moved; the stress bench's grow drew 3 of 17 rows again). Moved within their binade (between the same powers of two), positions are summed exactly moved (rounding commutes with a shift by a multiple of the unit in the last place), so they hold however near; across one, while further from the half than 32 units in the last place at their magnitude after the move. A row's unrounded origin summed across a power of two moves by 28.000008 for 28: within 1/64 of whole pixels that is a move (or a skip) by the whole pixels, held to the same margin plus that slack. |
| `Retained::stretchable` (port of `../gpui`'s row) | `crates/gpui/src/elements/retained.rs`, `crates/gpui/src/elements/retained/plan.rs` (`Drawn::stretch`) | A retained subtree whose root draws nothing from its size, only resized with nothing below it changed (a row stretched to a window's new width, `below_changed_since`), takes the new size and layout as its drawing's and is copied, moved or left out as if unchanged; upstream drew it again with its cards. mirin-metal's `draws_nothing_of_its_size` says which (it was a `GAP` shim). |

Fork changes upstream has in its own way (nothing to port; see
`docs/metal/gpui-next.md` for the evidence): layer-shell surfaces and the
screen they open on, typed float literals, idle windows that stop
committing, the loop outliving its last window (`QuitMode::Explicit`),
text input only while a field takes text, the toplevel's suspended state
(as window visibility), a layout reused only for the same truncation
width, a line cut from a copy of its runs, no-break spaces and quotes
(UAX #14), `DispatchEventResult` public, and scroll views painted at whole
device pixels (`Window::layout_bounds` snaps the element offset; always on,
so `MIRIN_METAL_SCROLL_SNAP=0` has no effect on this build).

To update: see `../README.md` (merge the `forks-upstream-next` branch), then
reconcile the changes above.

Checks: mirin-metal's tests on this fork, `cd crates/mirin-metal/next &&
cargo test --lib` (the shared sources, with `--features gpui-next` by
default), and `cargo clippy --all-targets -- -D warnings` there.
