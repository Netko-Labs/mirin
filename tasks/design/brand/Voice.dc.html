Voice — 01

Opinionated and warm

mirin has a point of view about how desktop apps should be built, and the writing says so. Warmth is not softness — it comes from being direct with someone you respect, not from exclamation marks.

Four rules, with the fix
1 · Take the position, then back it
“mirin offers an alternative approach to desktop development.”
“Electron's main process is Node because 2013 had no other option. Yours doesn't have to be.”
An opinion you can't support with a fact is marketing. Every claim gets a code block, a capture, or a link under it.
2 · Never punch down, never punch up for free
“The Electron killer.” · “Tauri makes you learn Rust.”
“Tauri ships a smaller binary. mirin ships one engine on every platform. Pick the tradeoff you can live with.”
Name competitors only to state a real, checkable difference. A pre-alpha project calling anything a killer is a joke at its own expense.
3 · Say what broke, then how to fix it
Oops! Something went wrong 😕
Error: ENOENT
CEF runtime missing for darwin-arm64.
Run: bun run fetch-cef
No apologies, no emoji, no performed alarm. Cause, then the exact command. Errors are the most-read copy in any framework.
4 · Cut the throat-clearing
“In this guide, we'll take a look at how you can simply get started with setting up windows.”
“A window is a config object. Here is one with native vibrancy:”
First sentence carries information. “In this guide”, “let's”, “simply”, and “just” are deletions, not edits.
Personality budget by surface
Landing
Full voice. Serif, metaphor, a joke that lands.
Release notes
Opinion allowed. Kome allowed. Breaking changes stay blunt.
Docs prose
Direct and warm. One aside per page, maximum.
CLI output
Terse. One flavour word total: brewing…
Errors & API
Zero. Someone is stuck. Personality here is cruelty.
The test: read it aloud. If it sounds like a person who has shipped a desktop app telling a colleague what they learned, it is right. If it sounds like a landing page, cut it.
