---
title: The agent skill
description: What mirin skill installs, and why keeping it fresh matters more than installing it.
---

```bash
bunx mirin skill
```

Installs the Mirin agent skill into `.claude/skills/mirin`. New projects get
it from `mirin init` already.

## Why it exists

Without it, an agent working in your repository infers the API from whatever
source it happens to read, and fills the gaps with something plausible from a
framework it knows better. The results compile and are wrong.

The skill states the API, the CLI, the layout and the verification loop
directly, so the agent works from what Mirin *is* rather than from what
Electron was.

## What it contains

- The API surface and the shapes it expects.
- The CLI commands, flags and exit codes.
- The verification loop — how to run `mirin check`, and where the event stream,
  screenshots and post-mortem land.
- The conventions a Mirin project follows.

## Keep it current

The skill ships with the CLI, so it moves when Mirin moves. Re-run
`mirin skill` after upgrading.

<Callout type="error">
A stale skill is worse than no skill. An agent will confidently write code
against an API that was removed two versions ago, and everything about the
output will look authoritative.
</Callout>

## Commit it

It is project configuration. Every contributor's agent should be working from
the same one, and a skill that lives only on your machine helps only you.
