Windows 10 and 11 on x64 and arm64. Every app-shell capability is implemented;
the platform is less exercised than macOS, so treat rough edges as likely and
report them.

## Windows and title bars

Frameless windows are the native path: Mirin handles `WM_NCCALCSIZE` and keeps
the DWM shadow. Dragging works through your CSS `-webkit-app-region` regions,
double-click on a drag region toggles maximize, and the OS move loop gives you
aero snap — drag to the top to maximize, to an edge to half-tile.

Window buttons are app-drawn rather than native caption buttons, so you style
them yourself and drive them through the client's `windowControls`.

## Transparency and acrylic

`transparent: true` or any `material` switches the window to off-screen
rendering, composited per-pixel into a layered window. Transparent windows pick
up a DWM acrylic blur backdrop.

## Installers

`mirin release` picks the best available packager:

1. Inno Setup, when `iscc` is on PATH
2. NSIS, when `makensis` is on PATH
3. A portable `.zip` otherwise

Updater artifacts are emitted either way.

## GPU selection

The default D3D11 ANGLE backend fails inside the GPU process on some hybrid-GPU
laptops. Mirin detects multi-GPU machines and selects the `gl` backend
automatically; single-GPU machines keep Chromium's D3D11 default. Override with
`MIRIN_ANGLE=<backend>` if you need to.

## Known gaps

- **No application menu bar.** Windows apps with a frameless title bar put menus
  in the UI, and Mirin follows that — `menu.setApplicationMenu` is a no-op.
  Popup and context menus work.
- **The `.exe` file icon in Explorer** is not set. The window, taskbar and
  Alt-Tab icons are. Bun's `--compile` has no icon flag, so this needs `rcedit`.
- The updater's in-place swap on Windows is implemented but not yet verified end
  to end.
